# 3차 — 실제 크롬으로 읽기 (2026-11-19 밤, 운영자 데스크톱)

## §19의 결론이 틀렸다. 바로잡는다.

2차까지 "RSS 26곳·브랜드 프레스룸 30곳 전부 차단"이라고 적었다. **원인을 잘못 짚었다.**
사이트가 막은 게 아니고, **이 세션의 계정 네트워크 허용 목록에 없어서** 게이트웨이가 403을 돌려준다.
증거: `curl https://api.newswire.co.kr/rss/industry/1304` → `connect_rejected`,
프록시 상태의 `recentRelayFailures`에 `gateway answered 403 to CONNECT (policy denial)`.

**→ 운영자가 claude.ai > Settings > Capabilities 에서 도메인을 허용하면 풀린다.**
즉 자동 수집이 가능해진다. "전화밖에 없다"고 적어 둔 곳들도 다시 봐야 한다.

## 읽기가 되는 브라우저 (중요)

- `mcp__claude-in-chrome__*` — **본문 읽기 됨.** navigate → get_page_text / read_page / find.
- `mcp__claude-device__lcl-Control_Chrome-*` — 탭 목록과 열기만 되고 **본문 읽기는 깨져 있다**
  (`get_page_content`, `execute_javascript` → "Google Chrome is not running", 탭 ID를 줘도 같다).
  → 페이지를 읽어야 할 때는 `claude-in-chrome` 쪽을 쓴다.

## 뉴스와이어 구조 해독 (연락처가 붙어 있는 유일한 경로)

| 용도 | URL 형태 |
|---|---|
| 기사 본문 | `https://www.newswire.co.kr/newsRead.php?no=<번호>` |
| 회사별 보도자료 전체 | `https://www.newswire.co.kr/?act=article&md=A10&no=<회사번호>&perpage=75` |
| 분야별 목록 | `https://www.newswire.co.kr/?md=A01&cat=<대>&cat1=<소>&perpage=75` |
| **분야별 RSS** | `https://api.newswire.co.kr/rss/industry/<소분류>` |

**산킷이 볼 분야 번호**
- `1304` 야외 레저 (대 1300 레저) — 4,082건 누적
- `903` 의류와 잡화 (대 900 생활) — 장비·의류 신제품이 여기로 분류된다 (스카르파 건이 1304와 903 양쪽)

**기사 하단에 반드시 붙는 블록**: `연락처` → 회사명 / 부서 / 담당자 이름 / 전화 / "이메일 보내기".
이메일은 폼 뒤에 숨어 있고 **이름·부서·전화는 그대로 노출된다.**
그리고 `<회사> 개요` 블록에 **그 회사가 독점수입하는 브랜드가 전부 적혀 있다.** 수입사 지도를 만들 수 있다.

  - 1차 결과: **기사 254건, 처음 본 회사 36곳** → `research/press_contacts_new.csv`
  - 신호율: 최신 피드 30건 중 6건, 백필은 목록 제목으로 걸러 정밀도가 더 높다.

**2. Mynewsdesk — 보도용 사진 자동 수집 작동.** `pipeline/fetch_presskit.py`
  - **`www.mynewsdesk.com/<슬러그>` 로 모든 뉴스룸에 닿는다.** 브랜드마다 도메인 허용이 필요 없다.
  - 사진은 `mnd-assets.mynewsdesk.com/image/upload/fl_attachment/<id>` 에서 원본으로 내려온다.
  - 라이선스 `Media Use` — 쓸 수 있다. 단 **무수정 + 촬영자 크레딧** (21절).
  - 1차 결과: atomic 5장, head 5장, haglofs 5장 = **15장 54MB**. 전부 Media Use.
  - 브랜드 슬러그 80개를 찍어 본 결과 **셋만 존재**했다. 비중은 작다. 과장하지 않는다.
  - 플레이라이트로 렌더링해야 사진 URL이 나온다 (목록이 자바스크립트로 실린다).
